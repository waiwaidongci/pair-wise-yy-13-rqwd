# hxyfront-62012 纺织染整小样管理 · 订单投产放行

纺织染整实验室小样台账的投产放行模块。针对"业务员仅凭评语通过就排大货、配方事后改动、生产线分不清该按哪版工艺放行"的问题，用**订单 + 当前工艺版本绑定的放行单**管住投产环节。

## 放行规则（`src/domain/`）

放行必须同时满足：

1. **色差**：样品 Lab 总色差 ΔE ≤ **0.8**；
2. **后整理一致**：样品实际后整理与当前工艺完全一致；
3. **保温达标**：样品保温时间 ≥ 工艺要求值；
4. **复核分离**：放行复核人具名，且不同于该工艺的调整人。

配套规则：

- **幂等提交**：当前工艺版本下已有有效放行时，重复提交沿用首次放行，不产生新单；
- **变更失效**：配方、后整理方式或保温时间变更 → 工艺升版，原有效放行自动标记失效（记录失效原因、时间、被哪一版取代）；只改浴比 / 温度曲线 / 说明不升版、不作废；
- **旧版可查**：失效放行连同放行时的工艺快照永久留档；工艺版本时间线可逐版展开；
- **订单三分类**（选订单时直接可见）：
  - 有效放行 —— 放行与当前工艺版本绑定，可排大货；
  - 待重评 —— 从未放行，或工艺变更后原放行已失效（另对"放行标记有效但版本对不上当前工艺"做防御性归类）；
  - 缺样品批次 —— 没有任何小样，无法办理放行。

## 分层结构

| 层 | 目录 | 职责 |
| --- | --- | --- |
| 规则 | `src/domain/` | 类型与纯函数：测控四项评估、工艺差异检测、升版、订单分组。不碰存储与 DOM |
| 存档 | `src/archive/` | 放行台账仓储（localStorage 持久化）、放行幂等、变更作废、版本归档、演示种子数据 |
| 页面 | `src/components/` + `src/App.tsx` | 订单分组列表、放行办理、工艺调整、版本/放行存档查询 |

## 本地运行

```bash
npm install
npm run dev        # http://localhost:62012
npm run build      # 类型检查 + 生产构建
npm run smoke      # 规则层 / 存档层逻辑冒烟测试
```
